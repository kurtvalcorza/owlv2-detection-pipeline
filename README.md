# OWLv2 base/16 ensemble open-vocabulary detection pipeline

DIMER inference wrapper for **OWLv2** (`google/owlv2-base-patch16-ensemble`), Google Research's open-vocabulary detector — a CLIP ViT-B/16 image tower whose 3,600 patch tokens each propose a box scored against caller-supplied text queries — pinned to an immutable Hugging Face revision and loaded only from a digest-verified local snapshot. The pipeline takes one image and a list of phrases and returns pixel-space boxes labelled with the best-matching phrase and the model's sigmoid score under a caller-owned threshold; there is no fixed class list, no non-maximum suppression, and no segmentation or tracking.

## Upstream alignment

- Model: `google/owlv2-base-patch16-ensemble`
- Revision: `cfd3195ba4ea9592eec887ded089f4c08eff231d`
- Upstream weight license: Apache-2.0
- Upstream task: zero-shot (text-conditioned) object detection
- Repository adaptation: **none**; inference only

## Quick start

```python
from PIL import Image
from owlv2_detection_pipeline import Owlv2DetectionPipeline

pipe = Owlv2DetectionPipeline.from_pretrained()          # stages + verifies weights/owlv2-base-patch16-ensemble first
result = pipe.detect(Image.open("street.jpg"), ["a photo of a stop sign", "a photo of a traffic light"])
for det in result["detections"]:                         # sorted by score, boxes are [x0, y0, x1, y1] pixels
    print(det["label"], det["box"], round(det["score"], 3))

# the threshold is the README example's value; override per call
result = pipe.detect(Image.open("street.jpg"), ["a photo of a cat"], threshold=0.3)
```

Install into a Python 3.12 environment that already holds the pinned dependencies with `pip install -e . --no-deps`; run `pytest -q -o addopts= tests` for the offline test suite (no weights needed). On a fresh clone the manifest is committed but the weights are not: `Owlv2DetectionPipeline.from_pretrained(allow_download=True)` fetches exactly the missing manifest-listed files at the pinned revision, then verifies them.

## Weights layout

```
weights/owlv2-base-patch16-ensemble/
  dimer-base-manifest.json   # modelId, revision, per-file bytes + SHA-256 (9 files)
  config.json                # Owlv2ForObjectDetection: 960px image, 16px patches, projection 512
  preprocessor_config.json   # pad to square (grey), resize 960x960, CLIP mean/std
  merges.txt  vocab.json  tokenizer_config.json  special_tokens_map.json  added_tokens.json   # CLIP BPE, 16 tokens
  model.safetensors          # git-ignored, 619,918,824 bytes
  README.md
```

`pytorch_model.bin` exists upstream and is deliberately not listed (pickle; DIMER does not accept `.bin`).

## Input ceilings and threshold

`MIN_IMAGE_SIDE = 16`, `MAX_IMAGE_SIDE = 4096`; `MAX_PROMPTS = 16` distinct phrases of at most `MAX_PROMPT_CHARS = 48` characters, each tokenised to at most `MAX_TEXT_TOKENS = 16` CLIP tokens (longer phrases are truncated by the tokenizer); `MAX_DETECTIONS = 3600` (one candidate per image patch); `DETECTION_THRESHOLD = 0.1` (the pinned README example's value). One image per call; the processor pads it to a square and resizes to 960×960. See `MODEL_CARD.md` for who owns tuning the threshold, the sigmoid score semantics, the absence of NMS and the measured CPU timings.

## Tutorials

[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/kurtvalcorza/owlv2-detection-pipeline/blob/main/tutorials/owlv2_detection_colab.ipynb)

`tutorials/owlv2_detection_colab.ipynb` is declared `TASK-INFERENCE` / `GUIDED` under DIMER Notebook Specification 2.0 and is **standalone** (§4): generated by `tools/build_notebook.py`, it carries the pipeline module, model identity, manifest digests and runtime pins, so the exported notebook runs without this repository (parity enforced by `tests/test_notebook_parity.py`). Its default `Run all` path draws a 640×480 scene in code (a black rectangle, a red disc, a blue triangle; no download) with three prompts naming them, surfaces the ceilings, exposes the caller-owned `threshold` as a form parameter, resolves the pinned model through the carried staging and verification path, validates the request through `validate_inputs` into an input manifest, detects through `Owlv2DetectionPipeline.detect`, writes an `evaluation_report` whose per-object `box_iou` entries are sanity evidence only (`sample-sanity` with the drawn reference boxes, `not-measurable` without; no mAP), and exports JSON, a detections CSV and an annotated PNG. BYOD (your image + comma-separated prompts) is optional and gated off by default. See `tutorials/README.md` for the registry and `docs/release-verification.md` for the release gate.

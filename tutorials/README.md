## What changed from the inference-only tutorial

The previous notebook (`TASK-INFERENCE`) detected three phrases in the drawn scene and reported `box_iou` against the drawn boxes as `sample-sanity`. This notebook keeps that scene and its inference contract as Section 5 and adds the adaptation contract for labelled (image, phrases, boxes) records around it: a real labelled box set fetched with per-file pins, a corpus-level protocol in the carried `metrics.py` (per-phrase AP at one IoU threshold, mAP, precision and recall at one score threshold) with two non-adapted baselines, a bounded fine-tuning of the class and box heads with the upstream matched objective on cached image features, box panels, the drawn scene re-detected after the shared heads were tuned, and an artifact that reloads. The per-image `evaluation_report` helper is unchanged; `pipe.evaluate` is the corpus-level stage (`measured` / `measured-small-sample`). The package now batches images through the towers (`detect_batch`, `EVAL_BATCH_SIZE` images per forward), runs its own post-processing (identical to the pinned processor's, so a tuned adapter applies to every call) and accepts zip/directory BYOD with a `boxes.csv`.

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's three modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 9-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9, MOD12):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh runtime lacks, at the pinned revision (never `main`); `verify_snapshot` re-hashes every entry and asserts the pinned `model.safetensors` digest and byte count before the processor or the model is constructed; `Owlv2DetectionPipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files through `Owlv2ForObjectDetection` / `Owlv2Processor` (`local_files_only=True`, `trust_remote_code=False`) in float32 and picks CUDA when it is visible. The upstream `pytorch_model.bin` is not listed and not used. No cell outside the carried modules calls `huggingface_hub`, `transformers`, `safetensors`, `pyarrow`, `urllib`, `torch.optim` or the model's processor directly.
- **Data (DAT1–DAT9, ST6):** the default sample is BCCD (`keremberke/blood-cell-object-detection` at the immutable parquet-conversion revision `22cf1b9d2367e799ab54a16774a2266e4f8ce9a9`, Public Domain): the three parquet files of the `full` configuration fetched whole in the carried `samples.py` (each refused unless its SHA-256 and byte count match `CORPUS_FILES`; 4.8 MB together), and `read_corpus` makes each image a record with one `{prompt, box}` per annotated cell (COCO `[x, y, w, h]` → `[x0, y0, x1, y1]`, class ids → `a platelet` / `a red blood cell` / `a white blood cell`); `build_sample_dataset(seed=SPLIT_SEED)` pools the 364 images and draws 260 / 40 / 64, and `check_split_disjoint` asserts no image (by decoded-pixel digest) is shared. The template adds a second *External access* bullet naming the host, the revision, the byte count and the licence.
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` per split + `check_split_disjoint` + refusal probes (validation, with three digests) → `validate_inputs` with the over-long-phrase refusal probe + `detect` on the drawn scene with structural checks + `evaluation_report` against the drawn boxes (inference contract) → `empty_baseline` + `grid_baseline` + `pipe.evaluate` on the frozen model with the per-phrase APs and four records' rows printed (baselines) → `pipe.adapt` (bounded fine-tuning) → `pipe.evaluate` on validation and test with the comparison (evaluation) → the box panels + the drawn scene again (inference) → `pipe.save_artifact` → `Owlv2DetectionPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** every score is an uncalibrated sigmoid of the best image–text logit, the threshold is the caller's, and there is no non-maximum suppression — the notebook says so before the first box; the corpus rates are AP at one IoU threshold and precision / recall at one score threshold over the reference boxes, with the predicted-box counts beside them; no acceptance threshold ships. The drawn scene re-detected after adaptation carries a `sample-sanity` verdict against boxes drawn in code, and the notebook names the missing dispersion.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the empty baseline, the grid-prior baseline and the frozen model are scored on the same 64 records as the adapted model, on the same rates at the same thresholds; every metric is labelled as one seeded split of one sample with no dispersion estimate. The recorded exact-blob run's numbers (in `../docs/release-verification.md`) are limited to one blood-smear set's three cell types on one seeded split.
- **Split integrity (SPL1–SPL8):** the split is seeded and image-disjoint; validation (40 records) selects the epoch on mAP and the test split is used for nothing but the final evaluation; the notebook states that images from one source, session or slide must be split together.
- **Ceilings (VAL6):** `MIN_IMAGE_SIDE` (16), `MAX_IMAGE_SIDE` (4096), `MAX_PROMPTS` (16), `MAX_PROMPT_CHARS` (48), `MAX_TEXT_TOKENS` (16), `MAX_DETECTIONS` / `NUM_PATCHES` (3600), `DETECTION_THRESHOLD` (0.1), `IOU_THRESHOLD` (0.5), the record bounds (8..5,000), `EVAL_BATCH_SIZE` (4) and the id pattern are stated in the Prerequisites and printed before the model runs; four dataset refusals and one over-long-phrase refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, one zip is read member by member (names flattened, no `extractall`) or a directory walked, the rows of `boxes.csv` become the records' boxes, and the records flow through the same validation, image-disjoint split, baselines, fine-tuning, evaluation, export and reload cells. The expected layout and the privacy guidance are stated in the Prerequisites and in Section 4, and the training split's box table is written to `outputs/owlv2_detection_train.csv`.
- Licence: the weights carry the Hub's Apache-2.0 tag and the notebook, README, card and `docs/WEIGHTS.md` say so; BCCD is Public Domain (the Roboflow Universe export) and is not redistributed — the export records the corpus name, repository, revision, files, licence, byte and row counts and the class phrases under `corpus`.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.

## Outputs

The default notebook path writes (under `outputs/`):

- `owlv2_detection_train.csv` — the training split's box table (one row per object: id, file name, phrase, box, image size, provenance)
- `owlv2_detection_example_record.png` — the first training record's photograph with its reference boxes outlined
- `owlv2_detection_input_manifest.json` — the inference-contract manifest (schema, the scene request, one recorded rejection finding)
- `owlv2_detection_scene_frozen.json` / `.png`, `owlv2_detection_scene_adapted.json` / `.png` — the drawn scene's detections, `evaluation_report` and annotated image before and after adaptation
- `owlv2_detection_evaluation_report.json` — baselines, frozen and adapted metrics on validation and test, the per-record rows, the per-phrase APs, the comparison, the adaptation history
- `owlv2_detection_examples/` — six held-out records as panels (the photograph with the reference boxes and with the adapted detections, the counts beneath)
- `owlv2_detection_adapter/` — `adapter.safetensors` + `manifest.json`
- `owlv2_detection_result.json` — `NOTEBOOK_SOURCE`, model identity, snapshot, corpus, the scene before and after adaptation with its reports, comparison, artifact digest, reload parity, runtime

The earlier record for the superseded `TASK-INFERENCE` carrier is kept in `../docs/release-verification.md`.
